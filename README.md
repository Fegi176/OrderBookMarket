# Order-Book Marketplace

A fictional stock exchange game on SpacetimeDB with a real price-time-priority order book. See [SPEC.md](SPEC.md) for the full design.

## Layout

```
server/              SpacetimeDB module (TypeScript)
  src/schema.ts      tables, indexes and the schema object
  src/engine.ts      matching engine, reservations, market orders, cancel, taker fees
  src/stops.ts       stop orders: place, cancel, and trigger after trades
  src/candles.ts     last price and one-minute candle roll-up
  src/bots.ts        market-maker and noise-trader bots
  src/news.ts        random news events that move each company's hidden fair value
  src/seasons.ts     weekly seasons: save standings, reset the market, start the next
  src/standings.ts   net-worth ranking shared by the leaderboard and season results
  src/index.ts       reducers, scheduled reducers, and private views
  tests/             engine, candle, bot/news, leaderboard, fee/stop and season tests on the SDK's in-process test datastore
client/              React + Vite trading view
  src/module_bindings/   generated by `spacetime generate` (do not edit)
  src/components/        trading view, portfolio and leaderboard pages
  src/lib/market.ts      pure depth, tick and portfolio calculations
  src/test/              test setup and a stand-in for spacetimedb/react
.github/workflows/       CI: typecheck, tests with coverage, and build for both packages
```

## Testing

Neither suite needs a running database. In `server/` or `client/`:

```bash
npm install
npm test
```

Run `npm run coverage` for a coverage report (HTML in `coverage/`).

| Suite | Tests | Statements | Branches |
| --- | --- | --- | --- |
| Server module | 57 | 99.7% | 93.6% |
| React client | 53 | 98.9% | 91.1% |

**Server** tests (`server/tests/`) run the real module against the SDK's in-process datastore. They call reducers as players, bots and the scheduler, then read the tables back.

| File | What it covers |
| --- | --- |
| `engine.test.ts` | Price-time matching, partial fills, self-trade skip, cancel, market orders |
| `engine.test.ts` | 1,000 random orders: total cash and shares conserved, and reservations equal what open orders and stops hold |
| `validation.test.ts` | Every rejection a client can trigger, each proven to roll back |
| `stretch.test.ts` | Fee maths and maker/taker rules, stop orders (trigger, cascade, failure, cancel) |
| `bots.test.ts` | Bot quoting, fair-value convergence, news, no row pile-up |
| `seasons.test.ts` | Season rollover and reset |
| `leaderboard.test.ts` | Leaderboard valuation |
| `candles.test.ts` | Candle roll-ups |
| `prune.test.ts` | History pruning |

**Client** tests (`client/src/**/*.test.tsx`) use Vitest, Testing Library and jsdom. `src/test/spacetime.ts` replaces the SpacetimeDB React hooks with fixtures and reducer spies, so components render without a server.
- Unit tests cover parsing and formatting. For example, `"0.29"` becomes exactly 29 cents, where `parseFloat` gives 28.999…
- Unit tests cover depth aggregation, trade ticks and portfolio maths.
- Component tests drive the order form, order book, portfolio, feeds, chart, seasons, Hall of Fame and page navigation as a user would. They assert on what's shown and the exact reducer arguments, including integer-cent prices.

## Run locally

Install the SpacetimeDB CLI from https://spacetimedb.com/install, then from the repo root:

```bash
spacetime start
```

```bash
spacetime publish --server local --module-path server order-book
```

```bash
cd client && npm install && npm run dev
```

Open http://localhost:5173. After changing tables or reducers, republish and regenerate the bindings with `npm run generate` in `client/`. If a change breaks the existing schema (for example a new column), add `--delete-data=always` to the publish command; this wipes the local database. Each browser profile gets its own identity, so use a second profile or private window to trade against yourself. You can also use `spacetime call --server local order-book place_limit_order BRKT sell 4300 5` from the CLI, which trades as its own identity.

`VITE_STDB_URI` and `VITE_STDB_DB` override the server address (`ws://localhost:3000`) and database name (`order-book`).

## Design notes

- Money is integer cents and quantities are whole shares, all `u64` (`bigint` in TS).
- Time priority uses a private `order_seq` counter, not timestamps.
- Placing an order reserves cash (buys, at the limit price) or shares (sells). Fills settle at the resting order's price and refund any price improvement to the buyer.
- Market orders are immediate-or-cancel: they fill what they can and the rest is cancelled, never rested. Buys stop when the next share is unaffordable. A market order that fills nothing is rejected.
- Market orders reject (empty book, no cash) before writing anything, so bots and stop triggers can catch the error safely.
- Self-trades are skipped: your own resting orders are passed over and stay on the book.
- Takers pay a 0.10% fee (`FEE_BPS`, rounded up to the cent) on the part of an order that executes on arrival. Resting (maker) orders pay nothing. A buy limit reserves the worst-case fee along with its cost and gets back whatever the actual fee didn't use. Fees go to the module-owned Exchange account, so total cash is still conserved. The fee is recorded per order as `feePaid`.
- Stop orders are stop-market orders kept in the private `stop_order` table. Clients read their own through the `my_stop_orders` view. A buy stop must sit above the last price and a sell stop below it.
  - Sell stops reserve their shares on placement. Buy stops reserve nothing and are checked for cash when they fire.
  - After every trade-producing reducer and each bot tick, `triggerStops` fires due stops oldest first as market orders. A fill can set off further stops in the same transaction.
  - A stop that can't execute is marked `failed`, with the reason in `note`, and a sell stop's shares are released.
- Seasons last one week (`SEASON_LENGTH_MICROS`). The public `season` table holds the active season and its end time, and `end_season` is scheduled for that exact moment. In one transaction it:
  1. saves the standings to `season_result`;
  2. deletes all orders and stop orders;
  3. resets every player to $100,000 and 100 shares of each company, the bots to their balances, and the Exchange to $0;
  4. puts prices and fair values back to each company's `listingPrice`;
  5. clears trades, candles and news;
  6. opens and schedules the next season.

  Accounts carry over, so nobody re-registers. To watch a rollover locally, shorten `SEASON_LENGTH_MICROS` temporarily and republish with `--delete-data=always`.
- History is pruned so tables stay small within a season (`prune.ts`). Bot activity otherwise adds roughly 0.7 trades and 0.7 order rows a second, and clients download a symbol's full trade and candle history when they subscribe.
  - Bots' filled and cancelled orders are deleted every tick.
  - Bot-vs-bot trades older than an hour, and candles older than three hours, are deleted every minute.
  - Anything involving a player is kept until the season resets.
- Order history comes free: filled and cancelled orders stay in `orders` with their status and fee, and the portfolio page lists them.
- Every trade updates the instrument's `lastPrice` and the current one-minute candle in the same transaction. The scheduled `roll_candles` runs each minute and opens a flat candle at the last price for symbols that haven't traded, so the chart has no gaps. Only the module itself may call it.
- Bots trade through the same engine as players, under two fixed module-owned identities flagged `isBot`.
  - `run_bots` runs every 3 seconds. The **Liquidity Bot** keeps 3 bids and 3 asks per symbol around an anchor that closes 25% of the gap between the last price and fair value each tick. Quotes are only replaced when incomplete or off-centre, and replaced quotes are deleted, so the order table doesn't fill with bot cancels.
  - The **Noise Bot** sends small market orders (35% chance per symbol per tick), leaning toward buying below fair value and selling above it.
  - Bot cash and shares are topped up when they run low. That top-up is the one place money enters the game besides registration.
- `fire_news_event` fires every 45-120 seconds. It picks a company, moves its hidden fair value by 1.5-12% up or down, and publishes a headline to the public `news` table. Each event schedules the next one. Fair value lives in the private `market_state` table, so players learn of moves from the news, not by reading the table.
- All randomness in bots and news comes from `ctx.random`, so reducers stay deterministic. Every scheduled reducer rejects calls from clients.
- `account` and `holding` are private tables. Clients read their own rows through the `my_account` and `my_holdings` views.
- The public `leaderboard` view publishes only each player's name, identity, net worth and starting net worth, never balances or positions. Net worth is cash (available plus reserved) plus every share at its symbol's last trade price; bots are excluded. Return % compares against `startingNetWorth`, which is recorded at registration. The portfolio page computes the same figure client-side from the player's own rows.
- The client subscribes per symbol: open orders, trades and candles for the selected symbol only. Depth is aggregated by price in the browser.
