# Order-Book Marketplace

A fictional stock exchange game on SpacetimeDB with a real price-time-priority order book. See [SPEC.md](SPEC.md) for the full design.

## Layout

```
server/              SpacetimeDB module (TypeScript)
  src/schema.ts      tables, indexes and the schema object
  src/engine.ts      matching engine, reservations, market orders, cancel
  src/candles.ts     last price and one-minute candle roll-up
  src/bots.ts        market-maker and noise-trader bots
  src/news.ts        random news events that move each company's hidden fair value
  src/index.ts       reducers, scheduled reducers, and private views
  tests/             engine, candle, bot/news and leaderboard tests on the SDK's in-process test datastore
client/              React + Vite trading view
  src/module_bindings/   generated by `spacetime generate` (do not edit)
  src/components/        trading view, portfolio and leaderboard pages
```

## Develop

Server tests need no running database:

```bash
cd server
npm install
npm test
```

## Run locally

Install the SpacetimeDB CLI from https://spacetimedb.com/install, then from the repo root:

```bash
spacetime start
```

```bash
spacetime publish --server local --module-path server order-book
```

```bash
cd client && npm install && npm run dev
```

Open http://localhost:5173. After changing tables or reducers, republish and regenerate the bindings with `npm run generate` in `client/`. If a change breaks the existing schema (for example a new column), add `--delete-data=always` to the publish command; this wipes the local database. Each browser profile gets its own identity, so use a second profile or private window to trade against yourself. You can also use `spacetime call --server local order-book place_limit_order BRKT sell 4300 5` from the CLI, which trades as its own identity.

`VITE_STDB_URI` and `VITE_STDB_DB` override the server address (`ws://localhost:3000`) and database name (`order-book`).

## Design notes

- Money is integer cents and quantities are whole shares, all `u64` (`bigint` in TS).
- Time priority uses a private `order_seq` counter, not timestamps.
- Placing an order reserves cash (buys, at the limit price) or shares (sells). Fills settle at the resting order's price and refund any price improvement to the buyer.
- Market orders are immediate-or-cancel: they fill what they can and the rest is cancelled, never rested. Buys stop when the next share is unaffordable. A market order that fills nothing is rejected.
- Self-trades are skipped: your own resting orders are passed over and stay on the book.
- Every trade updates the instrument's `lastPrice` and the current one-minute candle in the same transaction. The scheduled `roll_candles` runs each minute and opens a flat candle at the last price for symbols that haven't traded, so the chart has no gaps. Only the module itself may call it.
- Bots trade through the same engine as players, under two fixed module-owned identities flagged `isBot`.
  - `run_bots` runs every 3 seconds. The **Liquidity Bot** keeps 3 bids and 3 asks per symbol around an anchor that closes 25% of the gap between the last price and fair value each tick. Quotes are only replaced when incomplete or off-centre, and replaced quotes are deleted, so the order table doesn't fill with bot cancels.
  - The **Noise Bot** sends small market orders (35% chance per symbol per tick), leaning toward buying below fair value and selling above it.
  - Bot cash and shares are topped up when they run low. That top-up is the one place money enters the game besides registration.
- `fire_news_event` fires every 45-120 seconds. It picks a company, moves its hidden fair value by 1.5-12% up or down, and publishes a headline to the public `news` table. Each event schedules the next one. Fair value lives in the private `market_state` table, so players learn of moves from the news, not by reading the table.
- All randomness in bots and news comes from `ctx.random`, so reducers stay deterministic. Every scheduled reducer rejects calls from clients.
- `account` and `holding` are private tables. Clients read their own rows through the `my_account` and `my_holdings` views.
- The public `leaderboard` view publishes only each player's name, identity, net worth and starting net worth, never balances or positions. Net worth is cash (available plus reserved) plus every share at its symbol's last trade price; bots are excluded. Return % compares against `startingNetWorth`, which is recorded at registration. The portfolio page computes the same figure client-side from the player's own rows.
- The client subscribes per symbol: open orders, trades and candles for the selected symbol only. Depth is aggregated by price in the browser.
- Filled and cancelled orders stay in `orders` with their status, so order history is already there.
